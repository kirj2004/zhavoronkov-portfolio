# Портфолио-компоненты

Набор презентационных React-компонентов для лендинга, каталога кейсов и
страницы резюме. Созданы как перенос готовой статической вёрстки
`index.html` на React: разметка и классы совпадают один в один, чтобы
CSS можно было подключить без правок.

## Правило файла

Компонент **не содержит расчётов, запросов и доменной логики**. Он
принимает готовые данные и отдаёт разметку. Любая экономика — на
стороне бэкенда (Python). Нарушение этого правила приводит к тому, что
лендинг и полная страница кейса начинают считать по-разному и
расходятся в копейках.

## Что внутри

| Компонент | Назначение | Состояние |
|---|---|---|
| `HeroSection` | первый экран: заголовок, кнопки, показатели | нет |
| `PainCard` | карточка «боли» с раскрывающимся блоком | нет, `open`/`onToggle` от родителя |
| `ServiceCard` | карточка услуги | нет |
| `CaseCard` | карточка разбора с цифрами | нет |
| `Calculator` | поля ввода + вывод себестоимости | `useState` внутри формы |
| `ApiFlow` | схема пути данных «кабинет → API → расчёт → отчёт» | нет |
| `ContactItem` | один канал связи | нет |
| `ContactForm` | трёхшаговая форма заявки | `useState` внутри формы |
| `SectionHeader` | заголовок секции с подзаголовком и ссылкой | нет |
| `RoasBars` | столбцы «было / стало» | нет |

## Принятые решения

**`Calculator` не считает экономику.** Он отдаёт значения полей через
`onChange`, а результат приходит пропом `result` от родителя. Валюта
закупки вынесена наружу (`fields.currency`): если компонент сам
подставит символ валюты, пользователь увидит «¥» впереди цены и решит,
что это закупка в юанях, а не пересчёт.

**`CaseCard` принимает деньги строками.** Округлений внутри нет намеренно:
иначе отображаемое число может разойтись с числом на полной странице
кейса. Форматирование — на стороне бэкенда.

**`PainCard` не держит состояние.** Раскрытием управляет родитель. Если
каждая карточка заведёт своё, их нельзя будет закрыть разом и нельзя
будет связать с URL-якорем.

**Шаги `ContactForm` скрыты через `hidden` на `fieldset`,** а не через
`display: none` в CSS: нативная форма не отправит скрытые поля, и
пользователь не сможет уйти с третьего шага с пустыми обязательными
полями. Пропустить шаг с незаполненным полем нельзя — это проверяется
в `goTo`.

**`RoasBars` задаёт ширину через CSS-переменную `--v`,** а не inline
`width`: при пересчёте не трогается атрибут `style`. Шкала берётся как
максимум из данных, но не меньше 10% — иначе значения 3–4% займут весь
блок и будут выглядеть как успех.

**`SectionHeader` бросает ошибку без `idToProps`.** Внешняя `<section>`
объявляет `aria-labelledby` с этим id; молча разорвать ссылку хуже, чем
упасть на этапе разработки.

**`ApiFlow` фиксирует порядок узлов внутри компонента.** Переставить
шаги схемы — решение бэкенда, а не вёрстки. В `data-steps` и в
`aria-label` отдаётся строка «кабинет → API → расчёт → отчёт».

## Иконки

Все иконки — `lucide` через `<i data-lucide="…">`. Компонент не вызывает
`lucide.createIcons()`: это делает вызывающая страница один раз после
монтирования, иначе каждый компонент будет прогонять библиотеку заново.

## Что не сделано

- Нет тестов и сборки: в `mp-manager` нет `package.json` и React в
  зависимостях. Компоненты проверены только на баланс скобок и отсутствие
  мусора в тексте.
- Нет подключения к реальной странице: `index.html` остаётся статикой.
  Перенос на React — отдельная задача, требующая React в проекте.
- `Costcalc` внутри `Calculator` повторяет разметку готовой страницы, но
  расчётные формулы намеренно не перенесены: они живут в `econ_v3.py`.
